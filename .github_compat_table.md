# gh → forge compatibility (v0.2)

## Commands implemented

| gh command | forge command | Notes |
|---|---|---|
| `gh auth status` | `forge auth status` | Same shape (logged-in user + instance) |
| `gh auth login` | — | Not implemented; provision tokens via Forgejo web UI |
| `gh auth git-credential` | `forge auth git-credential` | `get`/`store`/`erase` protocol |
| `gh pr list` | `forge pr list` | Default tab cols: NUMBER TITLE BRANCH STATE |
| `gh pr view N` | `forge pr view N` | Multi-line readable output |
| `gh pr create` | `forge pr create` | Requires `--base`, `--head`, `--title`; `--body` optional |
| `gh pr merge N` | `forge pr merge N` | `--merge`/`--squash`/`--rebase` flags |
| `gh pr checks N` | `forge pr checks N` | Reads `/commits/{sha}/status` |
| `gh pr comment N` | `forge pr comment N` | `--body` required |
| `gh pr close N` | `forge pr close N` | PATCH state=closed |
| `gh pr reopen N` | `forge pr reopen N` | PATCH state=open |
| `gh pr edit N --base/--title/--body` | `forge pr edit N --base/--title/--body` | labels/assignees deferred to v0.3 |
| `gh run list -R o/r` | `forge run list -R o/r` | Filters: --branch, --status, --workflow (client-side) |
| `gh run view N --log` | `forge run log N [--container <name>]` | Deviation: noun-form; requires container exec (no Forgejo log API) |
| (no gh equivalent) | `forge pr log N [--container]` | forge-only: concat failed-run logs for PR head |
| `gh issue list` | `forge issue list` | Adds `&type=issues` filter (Forgejo quirk) |
| `gh issue view N` | `forge issue view N` | Multi-line readable output with body |
| `gh issue create` | `forge issue create` | Resolves `--label <name>` → integer ID (Forgejo quirk) |
| `gh issue close N` | `forge issue close N` | PATCH state=closed |
| `gh issue comment N` | `forge issue comment N` | Posts to `/issues/{N}/comments` |

## JSON field mapping

`forge`'s `--json` flag emits `gh`-compatible field names. See `src/forge/translate.py` for the authoritative `PR_FIELDS` and `ISSUE_FIELDS` translation tables.

Validated PR fields: `number`, `title`, `state`, `isDraft`, `author`, `headRefName`, `headRefOid`, `baseRefName`, `createdAt`, `url`, `labels`.

Validated issue fields: `number`, `title`, `body`, `state`, `author`, `createdAt`, `url`, `labels`.

Validated run fields: `id`, `runNumber`, `name`, `displayTitle`, `headBranch`, `headSha`, `status`, `event`, `url`, `createdAt`, `startedAt`, `updatedAt`, `workflowId`.

## Global flags

| flag | forge | gh equivalent |
|---|---|---|
| `--token <value>` | ✓ | `--token` (env: `GH_TOKEN`) |
| `--host <url>` | ✓ | `--hostname` (gh has weaker support for non-GitHub hosts) |
| `-R owner/repo` | ✓ | `-R` |
| `--debug` | ✓ | (gh uses `GH_DEBUG=api`) |

## Exit codes

| Code | Meaning | gh equivalent |
|---|---|---|
| 0 | Success | Same |
| 1 | Generic error | Same |
| 2 | Usage error (bad flag, unknown subcommand, unknown `--json` field) | Same |
| 3 | Not found (HTTP 404) | Same (`gh` returns 1 here) |
| 4 | Authentication / authorization failed (401/403) | Same (`gh` returns 1) |
| 5 | Server / network error (5xx / DNS / timeout) | Same |
| 6 | Validation error (422) | Same (`gh` returns 1) |

`forge`'s typed exit codes are more granular than `gh`'s (which collapses most errors to 1). Scripts that branch on `$?` after `gh` calls will still work after a `gh` → `forge` swap, since exit 0 vs nonzero is what matters in practice — but `forge`'s codes give richer information when wanted.

## Not implemented in v0.2

- `gh api`, `gh browse`, `gh repo *`, `gh release *`, `gh label *`, `gh milestone *`, `gh alias *`
- `--template` flag (use `--jq` instead — both shell out to system `jq`)
- Interactive `auth login`
- `pr ready`, `issue reopen` (deferred to v0.3)
- `workflow run` (workflow_dispatch trigger), `gist` subcommands (deferred to v0.3)
- `run view`, `run rerun` (no single-run API in Forgejo 11)
- `pr edit --add-label/--add-assignee/--milestone` (deferred to v0.3)

## Deviations from gh

| Surface | gh behavior | forge behavior | Reason |
|---|---|---|---|
| Error label format | Verbose multi-line | Single line: `forge <noun> <verb>: <label> (<code>): <msg>` | Single-line stderr is script-parseable |
| `--jq` failure | Exit 1 | Exit 1 | Same |
| Repo resolution from `git remote` | Trusts any github.com remote | Refuses non-matching hosts (e.g. `github.com` clone with `FORGEJO_HOST=git.stevenamoore.dev`) | Prevents silent cross-instance footguns |
| PR comment endpoint | `/issues/{N}/comments` (gh and forge match) | Same | Forgejo and GitHub share this quirk |
| `gh run view --log` | Streams from API | `forge run log` reads on-disk `.log.zst` via `docker exec` (Forgejo 11 has no log API) | Container gate required: `--container` or `FORGEJO_CONTAINER` |
| `gh run list` filters | API-side query params | `forge run list` filters client-side | Forgejo's `/actions/tasks` exposes only `limit`, no filter params |
| `pr log` | No gh equivalent | forge-only composite | Concat failed-run logs for PR head SHA — agentic-debug shape |
